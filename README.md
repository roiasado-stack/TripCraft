# TripCraft 🌴 — מלווה הטיולים שלך

אפליקציית ווב mobile-first בעברית (RTL) לתכנון וליווי טיולים — למטיילים פרטיים ולסוכני נסיעות.

בנויה כ-**מוצר אמיתי**: חשבונות משתמשים, מסד נתונים, אחסון קבצים פרטי, והרשאות (RLS) ברמת השורה.

- **באוויר:** https://tripcraft-lac.vercel.app (Vercel + Supabase)
- **פרויקט גמר** בקורס AI Agents & Automation Specialist. שכבת ה-AI כוללת:
  - **סוכן עם כלים** שלא כותב דבר בלי אישור המשתמש.
  - **מקור ידע (RAG)** עם מקורות מצוטטים.
  - **Evaluation**: 30 שאלות עם ריצת בסיס (`evals/`).
  - **Monitoring** ותקרות הוצאה יומיות (`/admin/monitoring`).
  - **אוטומציית n8n** (`n8n/`).

## מה יש באפליקציה

**התחברות**
- הרשמה/כניסה במייל+סיסמה, וגם Google.
- כל משתמש רואה **רק** טיולים שהוא הבעלים שלהם או חבר מאושר בהם (נאכף במסד הנתונים, לא רק ב-UI).
- איפוס סיסמה במייל (`/reset-password`).
- תפקידים בטבלה נפרדת `user_roles` (admin / agent / traveler) — לעולם לא על הפרופיל.

**אשף יצירת טיול (4 שלבים)**
1. יעד, שם, תאריכים, סוג טיול, תקציב, אייקון.
2. משתתפים: שם + גיל מדויק או טווח גילאים + העדפות (חוף, אוכל, קניות, היסטוריה, לילה, ספורט, נגישות, כשרות, צמחוני).
3. טיסות, לינה, העברות/רכב שכור.
4. סיכום ויצירה.

**מסכי הטיול**
- **בית** — ספירה לאחור, הטיסה הקרובה, מה קורה היום, סיכום לינה.
- **מסלול** — לפי ימים, הוספה/עריכה/מחיקה של פריטים עם שעה, קטגוריה ומיקום.
- **מומלצים** — אטרקציות/מסעדות/טיפים, סינון לפי סוג, סימון "אהבתי", הוספה למסלול.
- **מסמכים** — העלאה מהמחשב/מהטלפון (כולל צילום ישיר) לאחסון פרטי, או הדבקת קישור חיצוני (Drive/Dropbox/OneDrive). כל מסמך משויך לקטגוריה ולנוסע.
- **צ'קליסט** — רשימה משותפת ואישית, סימון פריטים, ו"רשימה מומלצת" חכמה שמותאמת אוטומטית למשתתפים (תינוקות, ילדים, חוף, ספורט…).
- **משתתפים** ו**תחבורה** — הנוסעים, הטיסות, הלינה והרכב.
- **שאל את הסוכן** — שיחה בעברית על הטיול, עם כלים (ראו בהמשך).

**ייבוא במקום הקלדה**
- מעלים PDF או צילום של אישור טיסה, מלון, רכב או רשימת נוסעים, ו-Claude מחלץ את הפרטים. המשתמש בודק ומאשר לפני שמשהו נשמר.

**חברי טיול ותפקידים**
- הבעלים מזמין בקישור לפי תפקיד (`/join/:token`): צופה, משתתף או עורך. הבעלים מאשר כל מצטרף, ויכול להסיר אותו.
- ההרשאות נאכפות ב-RLS (מיגרציה 015), והממשק רק משקף אותן (`src/lib/permissions.ts`).

**כשרות ושבת**
- חיפוש מסעדות, חנויות ובתי חב"ד כשרים סביב היעד, עם רמת אמון לכל תוצאה (מאומת מול מקור ידע / נמצא במפה בלבד).
- זמני כניסת שבת וחג לפי היעד ותאריכי הטיול (Hebcal).

**נסו בעצמכם**
- גולש בלי חשבון יכול לשכפל טיול הדגמה ולשחק בו. הוא מקבל תקציב AI קטן, בלי שיתוף והעלאת קבצים, והנתונים נמחקים אחרי 7 ימים.

**סוכני נסיעות**
- שיתוף קישור לצפייה בלבד (`/share/:slug`) — בלי התחברות, בלי גישה למסמכים הפרטיים.
- מיתוג הסוכנות (שם + צבע) מוצג בעמוד המשותף.
- שכפול טיול כתבנית לטיול חדש (מעתיק משתתפים, מסלול, צ'קליסט — ומאפס סימוני "בוצע").

**עיצוב**
- ויברנטי וקייצי: טורקיז ים, קורל חם, צהוב שמש. פינות מעוגלות, כפתורים גדולים.
- מצב כהה מלא + RTL מלא.

## הפעלה — 3 שלבים

### 1. פתיחת פרויקט Supabase (חינמי, ~3 דקות)

1. היכנס ל-[supabase.com](https://supabase.com) → **New project**.
2. בחר שם, סיסמת דאטהבייס, ואזור קרוב (למשל **Frankfurt**).
3. המתן כדקה עד שהפרויקט מוכן.

### 2. הרצת הסכימה

1. בפרויקט → **SQL Editor** → **New query**.
2. הדבק והרץ את [`supabase/schema.sql`](supabase/schema.sql). זו סכימת הבסיס: טבלאות, RLS, טבלת התפקידים, טריגר פרופיל ודלי אחסון פרטי.
3. הדבק והרץ, **לפי הסדר**, כל קובץ ב-[`supabase/migrations/`](supabase/migrations/) (`002` עד `020`).

הסכימה המלאה היא `schema.sql` ועוד כל המיגרציות. את `schema.sql` מריצים רק על פרויקט חדש: מיגרציה 015 מחליפה את מדיניות ההרשאות שלו, והרצה חוזרת שלו על מסד קיים תחזיר את המדיניות הישנה.

### 3. חיבור המפתחות

1. בפרויקט → **Project Settings** → **API**.
2. העתק את ה-**Project URL** ואת מפתח ה-**anon / publishable**.
3. צור קובץ `.env` בתיקיית הפרויקט (אפשר להעתיק מ-`.env.example`):

```
VITE_SUPABASE_URL="https://YOUR-PROJECT.supabase.co"
VITE_SUPABASE_PUBLISHABLE_KEY="your-anon-key"
```

4. התקנה והרצה:

```bash
npm install
```

```bash
npm run dev
```

האפליקציה תיפתח ב-http://localhost:5173

> אם לא הגדרת `.env` עדיין — האפליקציה תציג מסך הסבר ידידותי במקום לקרוס.

## הפעלת יצירת התוכן ב-AI (אופציונלי)

כפתורי ה-**AI** (במסך "מסלול" ובמסך "מומלצים") קוראים ל-Edge Function שרצה בצד השרת, כדי שמפתח ה-API לעולם לא ייחשף בדפדפן.

```bash
npm i -g supabase
```

```bash
supabase link --project-ref YOUR-PROJECT-REF
```

```bash
supabase secrets set ANTHROPIC_API_KEY=sk-ant-your-key
```

```bash
supabase functions deploy generate
```

```bash
supabase functions deploy ask
```

הפונקציה נמצאת ב-[`supabase/functions/generate/index.ts`](supabase/functions/generate/index.ts). היא בודקת את התפקיד של המשתמש בטיול לפני שהיא מייצרת משהו (מסלול: בעלים ועורך; מומלצים וצ'קליסט: גם משתתף; צופה לא מוציא תקציב AI), ומייצרת:
- **מומלצים** — 8 אטרקציות, 6 מסעדות, 4 טיפים, מותאמים לגילאים ולהעדפות.
- **מסלול** — 3–5 פריטים לכל יום, לפי סדר הגיוני.
- **צ'קליסט** — 15–25 פריטים מותאמים.

לחיצה חוזרת על כפתור ה-AI מוסיפה רק דברים חדשים: הפונקציה מעבירה למודל את מה שכבר שמור בטיול, ומסננת פריט שהשם שלו כבר קיים.

עם כפתור "צור מחדש" אפשר לכוונן: יותר ידידותי לילדים / יותר רגוע / תקציב נמוך / יותר אקטיבי.

### תמונות ומפה

כל פריט ב"מומלצים" ו"מסלול" — גם כאלה שנוצרו ב-AI וגם שנוספו ידנית — מקבל אוטומטית תמונת קאבר וקואורדינטות למפה, בלי שהמשתמש מקליד קישור או מיקום בעצמו. **לא צריך שום מפתח בשביל התמונות.**

התמונה היא התמונה הראשית של הערך בוויקיפדיה האנגלית על המקום הספציפי הזה (למשל "Tombs of the Kings (Paphos)"), לפי כותרת מדויקת — בפריטים שנוצרו ב-AI המודל מחזיר את כותרת הערך, ובהוספה ידנית קריאה קטנה ל-Claude מזהה אותה. אין חיפוש חופשי כגיבוי, בכוונה: מסעדה, מלון או מקום בלי ערך משלו לא מקבלים תמונה, והכרטיס מציג את התצוגה החלופית (גרדיאנט + אייקון) — עדיף על תמונה של מקום אחר. תמונות שנמצאו נשמרות במטמון בטבלה `photo_cache` (מיגרציה 012, service-role בלבד). את `UNSPLASH_ACCESS_KEY` מגרסאות קודמות אפשר למחוק — הוא כבר לא בשימוש.

> תמונות מוויקימדיה מופצות ברישיונות Creative Commons (למשל CC BY-SA) שמחייבים ייחוס. כל תמונה מציגה קישור ⓘ לדף הקובץ (יוצר ורישיון), ויש גם עמוד `/credits`.

קואורדינטות למפה מגיעות מ-Nominatim (OpenStreetMap) בהוספה ידנית, וישירות מה-AI בהמלצות/מסלול שנוצרים ב-AI — גם לזה לא צריך מפתח.

### שאל את הסוכן

המסך **"שאל את הסוכן"** (כניסה ממסך הבית וממסך "מומלצים") הוא שיחה בעברית על הטיול הספציפי — היעד, התאריכים, המשתתפים והמסלול שכבר נבנה. לצד התשובה הסוכן יכול להחזיר כרטיסי המלצה עם כפתור הוספה למומלצים או למסלול.

הפונקציה נמצאת ב-[`supabase/functions/ask/index.ts`](supabase/functions/ask/index.ts) ורצה על `claude-haiku-4-5` (קבוע `MODEL` ב-`prompt.ts`). יש לה שלושה כלים: `add_to_itinerary`, `add_suggestion` ו-`find_kosher`. כלי שכותב לטיול רק מציע כרטיס, והמשתמש מאשר אותו בלחיצה.

- **הרשאות:** הפונקציה בודקת את התפקיד בטיול (`trip_role`). בעלים, עורך ומשתתף יכולים לשאול. צופה מקבל רק את חיפוש הכשרות. אין לה חשיפה למבקרים בדף השיתוף.
- **מקור ידע (RAG):** כשרות, בתי חב"ד ושבת נשלפים מ-pgvector (מיגרציה 006) עם embeddings של Voyage AI, והתשובה מצטטת את המקור.
- **שמירת השיחה:** השיחה נשמרת בטבלה `trip_chat_messages` (מיגרציה 003), ללא הרשאת קריאה ל-`anon`.

> שים לב: מפתח ה-API הוא סוד יחיד של הפרויקט — כל שאלה נופלת על חשבון בעל הפרויקט, לא על המשתמש.

> גם בלי ה-AI, כפתור **"רשימה מומלצת"** בצ'קליסט עובד לגמרי — הוא בונה רשימה חכמה מותאמת אישית ללא צורך בשרת.

## פריסה לאוויר (חינם)

```bash
npm run build
```

התיקייה `dist/` מוכנה לפריסה. הכי פשוט:

- **Vercel** או **Netlify** — חבר את הריפו, הגדר את שני משתני הסביבה (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`), ופרוס.
- חשוב: הגדר **SPA rewrite** (כל הנתיבים → `index.html`) כדי שקישורי `/share/...` יעבדו.

אחרי הפריסה, הוסף את הדומיין ל-Redirect URLs ב-Supabase.

### התקנה כאפליקציה בטלפון

האפליקציה mobile-first ועובדת מצוין דרך הדפדפן. בטלפון: **שתף → הוסף למסך הבית** — היא נפתחת במסך מלא בלי סרגל כתובת, עם השם והאייקון של TripCraft.

זה עובד דרך [`public/manifest.webmanifest`](public/manifest.webmanifest) והאייקונים שלידו (`icon-192`, `icon-512`, `apple-touch-icon`), שנוצרים מסימן המותג ב-[`marketing/logo/`](marketing/logo/). ב-iOS הקובץ הזה לא מספיק — הוא קורא את תגיות ה-`apple-mobile-web-app-*` ב-`index.html`, ולכן שתי הדרכים מוגדרות.

> **מגבלה:** ההתקנה עובדת רק דרך "הוסף למסך הבית" בתפריט. כרום באנדרואיד לא יציע התקנה אוטומטית כי אין Service Worker — והוספת אחד גם תוסיף מצב אופליין, שהוא מחוץ להיקף של הפרויקט כרגע.

לחנויות האפליקציות (App Store / Google Play) אפשר לעטוף אותה מאוחר יותר ב-Capacitor בלי לשנות את הקוד.

## איכות: בדיקות, Evals ו-Monitoring

```bash
npm run check
```

זה השער לפני כל מיזוג: typecheck, ESLint (חוקים שתופסים באגים בלבד), בדיקת חוקי הריפו (`scripts/check-rules.mjs`: RTL, צבעים, ייבואים, מיגרציות), בדיקות יחידה (Vitest) ו-build.

```bash
npm run test:db
```

בודק את ההרשאות ("מי רואה מה") מול מסד Supabase **מקומי** ב-Docker: הבעלים, כל תפקיד, זר, מבקר אנונימי בדף השיתוף ומשתמש הדגמה. כל קובץ ב-`supabase/tests/` רץ בתוך טרנזקציה שמתבטלת בסוף.

```bash
npm run evals
```

מריץ 30 שאלות בעברית על הסוכן (20 שליפת עובדות ו-10 שבהן הוא צריך לסרב) ומשווה ל-`evals/baseline.json`. הריצה של קו הבסיס: 100% דיוק, 0% הזיות.

- **Monitoring:** כל קריאה למודל נרשמת בטבלה `agent_runs` (עלות, זמן, טוקנים). מסך `/admin/monitoring` מציג אותן לאדמין. יש תקרת הוצאה יומית למשתמש, למשתמשי הדגמה ולאפליקציה כולה.
- **אוטומציה:** ב-`n8n/` יש שני workflows: תזכורת שבוע לפני יציאה, ו-Error Workflow שמתריע על כשל.

## אבטחה

- **RLS על כל טבלה.** משתמש ניגש רק לטיולים שהוא הבעלים שלהם או חבר מאושר בהם, ובהתאם לתפקיד (צופה / משתתף / עורך).
- **תפקידים בטבלה נפרדת** (`user_roles`) עם פונקציית `has_role()` מסוג `SECURITY DEFINER`. לא ניתן להעלות הרשאות מהלקוח.
- **מסמכים פרטיים לחלוטין.** דלי אחסון סגור, וגישה רק דרך קישורים חתומים (signed URLs) לזמן מוגבל. המסמכים לא נחשפים גם בטיול משותף.
- **דף שיתוף ציבורי** (`/share/:slug`). קריאה בלבד, דרך פונקציה אחת (`get_shared_trip`) שמחזירה רק את מה שהדף מציג. אין לו מספרי הזמנה, משתתפים, מסמכים או הערות. אין לאף טבלה הרשאת `anon`.
- **מפתח ה-AI** נשמר כסוד בצד השרת בלבד, עם תקרות הוצאה יומיות.
