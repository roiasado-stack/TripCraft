# TripCraft 🌴 — מלווה הטיולים שלך

אפליקציית ווב mobile-first בעברית (RTL) לתכנון וליווי טיולים — למטיילים פרטיים ולסוכני נסיעות.

בנויה כ-**מוצר אמיתי**: חשבונות משתמשים, מסד נתונים, אחסון קבצים פרטי, והרשאות (RLS) ברמת השורה.

---

## מה יש באפליקציה

**התחברות**
- הרשמה/כניסה במייל+סיסמה, וגם Google.
- כל משתמש רואה **רק** את הטיולים שלו (נאכף במסד הנתונים, לא רק ב-UI).
- תפקידים בטבלה נפרדת `user_roles` (admin / agent / traveler) — לעולם לא על הפרופיל.

**אשף יצירת טיול (4 שלבים)**
1. יעד, שם, תאריכים, סוג טיול, תקציב, אייקון.
2. משתתפים: שם + גיל מדויק או טווח גילאים + העדפות (חוף, אוכל, קניות, היסטוריה, לילה, ספורט, נגישות, כשרות, צמחוני).
3. טיסות, לינה, העברות/רכב שכור.
4. סיכום ויצירה.

**5 מסכי הטיול (טאב-בר תחתון)**
- **בית** — ספירה לאחור, הטיסה הקרובה, מה קורה היום, סיכום לינה.
- **מסלול** — לפי ימים, הוספה/עריכה/מחיקה של פריטים עם שעה, קטגוריה ומיקום.
- **מומלצים** — אטרקציות/מסעדות/טיפים, סינון לפי סוג, סימון "אהבתי", הוספה למסלול.
- **מסמכים** — העלאה מהמחשב/מהטלפון (כולל צילום ישיר) לאחסון פרטי, או הדבקת קישור חיצוני (Drive/Dropbox/OneDrive). כל מסמך משויך לקטגוריה ולנוסע.
- **צ'קליסט** — רשימה משותפת ואישית, סימון פריטים, ו"רשימה מומלצת" חכמה שמותאמת אוטומטית למשתתפים (תינוקות, ילדים, חוף, ספורט…).

**סוכני נסיעות**
- שיתוף קישור לצפייה בלבד (`/share/:slug`) — בלי התחברות, בלי גישה למסמכים הפרטיים.
- מיתוג הסוכנות (שם + צבע) מוצג בעמוד המשותף.
- שכפול טיול כתבנית לטיול חדש (מעתיק משתתפים, מסלול, צ'קליסט — ומאפס סימוני "בוצע").

**עיצוב**
- ויברנטי וקייצי: טורקיז ים, קורל חם, צהוב שמש. פינות מעוגלות, כפתורים גדולים.
- מצב כהה מלא + RTL מלא.

## הפעלה — 3 שלבים

### 1. פתיחת פרויקט Supabase (חינמי, ~3 דקות)

1. היכנס ל-[supabase.com](https://supabase.com) → **New project**.
2. בחר שם, סיסמת דאטהבייס, ואזור קרוב (למשל **Frankfurt**).
3. המתן כדקה עד שהפרויקט מוכן.

### 2. הרצת הסכימה

1. בפרויקט → **SQL Editor** → **New query**.
2. העתק את כל התוכן של [`supabase/schema.sql`](supabase/schema.sql) והדבק.
3. לחץ **Run**.

זה בונה את הכל: 11 טבלאות, מדיניות RLS, טבלת התפקידים, טריגר שיוצר פרופיל+תפקיד לכל משתמש חדש, ודלי אחסון פרטי למסמכים.

### 3. חיבור המפתחות

1. בפרויקט → **Project Settings** → **API**.
2. העתק את ה-**Project URL** ואת מפתח ה-**anon / publishable**.
3. צור קובץ `.env` בתיקיית הפרויקט (אפשר להעתיק מ-`.env.example`):

```
VITE_SUPABASE_URL="https://YOUR-PROJECT.supabase.co"
VITE_SUPABASE_PUBLISHABLE_KEY="your-anon-key"
```

4. התקנה והרצה:

```bash
npm install
```

```bash
npm run dev
```

האפליקציה תיפתח ב-http://localhost:5173

> אם לא הגדרת `.env` עדיין — האפליקציה תציג מסך הסבר ידידותי במקום לקרוס.

## הפעלת התחברות עם Google (אופציונלי)

ב-Supabase → **Authentication** → **Providers** → **Google** → הפעל, והזן Client ID + Secret מ-[Google Cloud Console](https://console.cloud.google.com/apis/credentials).

ב-**Authentication → URL Configuration** הוסף ל-Redirect URLs:
- `http://localhost:5173/**` (לפיתוח)
- את כתובת הפרודקשן שלך

## הפעלת יצירת התוכן ב-AI (אופציונלי)

כפתורי ה-**AI** (במסך "מסלול" ובמסך "מומלצים") קוראים ל-Edge Function שרצה בצד השרת, כדי שמפתח ה-API לעולם לא ייחשף בדפדפן.

```bash
npm i -g supabase
```

```bash
supabase link --project-ref YOUR-PROJECT-REF
```

```bash
supabase secrets set ANTHROPIC_API_KEY=sk-ant-your-key
```

```bash
supabase functions deploy generate
```

```bash
supabase functions deploy ask
```

הפונקציה נמצאת ב-[`supabase/functions/generate/index.ts`](supabase/functions/generate/index.ts). היא מוודאת שהמשתמש הוא הבעלים של הטיול לפני שהיא מייצרת משהו, ומייצרת:
- **מומלצים** — 8 אטרקציות, 6 מסעדות, 4 טיפים, מותאמים לגילאים ולהעדפות.
- **מסלול** — 3–5 פריטים לכל יום, לפי סדר הגיוני.
- **צ'קליסט** — 15–25 פריטים מותאמים.

עם כפתור "צור מחדש" אפשר לכוונן: יותר ידידותי לילדים / יותר רגוע / תקציב נמוך / יותר אקטיבי.

### שאל את הסוכן

המסך **"שאל את הסוכן"** (כניסה ממסך הבית וממסך "מומלצים") הוא שיחה בעברית על הטיול הספציפי — היעד, התאריכים, המשתתפים והמסלול שכבר נבנה. לצד התשובה הסוכן יכול להחזיר כרטיסי המלצה עם כפתור הוספה למומלצים או למסלול.

הפונקציה נמצאת ב-[`supabase/functions/ask/index.ts`](supabase/functions/ask/index.ts) ורצה על `claude-haiku-4-5` (קבוע `MODEL` בראש הקובץ). היא **לבעלים בלבד** — היא משווה את `user_id` של הטיול למשתמש שב-JWT, ואין לה חשיפה למבקרים בדף השיתוף. השיחה נשמרת בטבלה `trip_chat_messages` (מיגרציה 003), שגם היא ללא הרשאת קריאה ל-`anon`.

> שים לב: מפתח ה-API הוא סוד יחיד של הפרויקט — כל שאלה נופלת על חשבון בעל הפרויקט, לא על המשתמש.

> גם בלי ה-AI, כפתור **"רשימה מומלצת"** בצ'קליסט עובד לגמרי — הוא בונה רשימה חכמה מותאמת אישית ללא צורך בשרת.

## פריסה לאוויר (חינם)

```bash
npm run build
```

התיקייה `dist/` מוכנה לפריסה. הכי פשוט:

- **Vercel** או **Netlify** — חבר את הריפו, הגדר את שני משתני הסביבה (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`), ופרוס.
- חשוב: הגדר **SPA rewrite** (כל הנתיבים → `index.html`) כדי שקישורי `/share/...` יעבדו.

אחרי הפריסה, הוסף את הדומיין ל-Redirect URLs ב-Supabase.

### התקנה כאפליקציה בטלפון

האפליקציה mobile-first ועובדת מצוין דרך הדפדפן. בטלפון: **שתף → הוסף למסך הבית** — היא נפתחת במסך מלא בלי סרגל כתובת, עם השם והאייקון של TripCraft.

זה עובד דרך [`public/manifest.webmanifest`](public/manifest.webmanifest) והאייקונים שלידו (`icon-192`, `icon-512`, `apple-touch-icon`), שנוצרים מסימן המותג ב-[`marketing/logo/`](marketing/logo/). ב-iOS הקובץ הזה לא מספיק — הוא קורא את תגיות ה-`apple-mobile-web-app-*` ב-`index.html`, ולכן שתי הדרכים מוגדרות.

> **מגבלה:** ההתקנה עובדת רק דרך "הוסף למסך הבית" בתפריט. כרום באנדרואיד לא יציע התקנה אוטומטית כי אין Service Worker — והוספת אחד גם תוסיף מצב אופליין, שהוא מחוץ להיקף של הפרויקט כרגע.

לחנויות האפליקציות (App Store / Google Play) אפשר לעטוף אותה מאוחר יותר ב-Capacitor בלי לשנות את הקוד.

## מבנה הפרויקט

```
src/
  components/     רכיבי UI משותפים (ui.tsx, TripCard, TripHeader, ShareSheet…)
  hooks/          use-auth (התחברות ותפקידים), use-theme (מצב כהה), use-toast
  lib/            supabase (חיבור), types, trip-options (קבועים בעברית), ai, starter
  routes/         AuthPage, TripsListPage, WizardPage, SettingsPage, SharePage
    trip/         TripLayout (טאב-בר) + המסכים, כולל AskTab (הסוכן)
  styles.css      מערכת העיצוב (צבעים, גרדיאנטים, מצב כהה)
supabase/
  schema.sql      כל הסכימה — הרץ פעם אחת
  migrations/     שינויים מצטברים לסכימה (002, 003…)
  functions/generate/  ה-Edge Function ליצירת תוכן AI
  functions/ask/       ה-Edge Function של סוכן השאלות
```

## אבטחה

- **RLS על כל טבלה** — משתמש יכול לגשת רק לשורות של הטיולים שלו.
- **תפקידים בטבלה נפרדת** (`user_roles`) עם פונקציית `has_role()` מסוג `SECURITY DEFINER` — לא ניתן להעלות הרשאות מהלקוח.
- **מסמכים פרטיים לחלוטין** — דלי אחסון סגור, גישה רק דרך קישורים חתומים (signed URLs) לזמן מוגבל. גם בטיול משותף, המסמכים לא נחשפים.
- **טיול משותף** — נחשף לקריאה בלבד, ורק כאשר `is_shared = true`.
- **מפתח ה-AI** נשמר כסוד בצד השרת בלבד.
